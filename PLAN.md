# PLAN.md

## Phase 1: Phase 1 — Shared foundations: date helpers + shared types (~3 files)

Create the shared date helpers and extend shared types. Files: (1) NEW `src/shared/date/accrual.ts` — export `startOfUtcDay(date: Date): Date`, `addMonths(date: Date, months: number): Date`, and `periodContaining(anchor: Date, accrualMonths: number, date: Date): { start: Date; end: Date }`. These are pure UTC arithmetic copied verbatim from the private helpers currently in `src/modules/leave/leave.service.ts` (startOfUtcDay, addMonths, periodContaining) and `src/modules/balance/balance.service.ts` (addMonths) — do NOT change their semantics. `periodContaining` keeps the 10,000-iteration safety bound and throws ConflictError when `date < anchor`. (2) NEW `src/shared/date/index.ts` re-exporting all three. (3) EDIT `src/shared/types/index.ts` — add `export interface EmployeeProfile { id: string; employeeNumber: string; firstName: string; lastName: string; email: string; role: EmployeeRole; managerId: string | null; department: string; hireDate: Date; employmentStatus: EmploymentStatus; }` (no passwordHash, no terminationDate) and add `employeeIds?: string[]` to `LeaveRequestQueryParams`. (4) NEW `tests/unit/shared/date.test.ts` — Jest tests for startOfUtcDay/addMonths/periodContaining including a non-UTC case (set `process.env.TZ = 'Asia/Riyadh'` in a describe block) and month-end clamping. Do NOT yet refactor leave.service.ts or balance.service.ts to import these — that is a later phase.

## Phase 4: Phase 4 — Auth module: POST /auth/login (~4 files)

Build the auth module and login endpoint. Files: (1) NEW `src/modules/auth/auth.service.ts` — declare `IAuthService` with `login(email: string, password: string): Promise<{ token: string; profile: EmployeeProfile }>` and implement `AuthService`. Constructor injects `IEmployeeService` (from `../employee`). `login` calls `employeeService.getEmployeeByEmail(email)`, then `bcrypt.compare(password, employee.passwordHash ?? '')`; on a missing employee OR a failed compare throw the SAME `UnauthorizedError('Invalid email or password')` (indistinguishable). On success call `signToken({ id: employee.id, role: employee.role })` from `src/shared/auth` and return `{ token, profile: toEmployeeProfile(employee) }` — never include passwordHash. Use the existing `bcrypt` (^5.0.1) and `jsonwebtoken` (^8.5.1) deps; do not add libraries. (2) NEW `src/modules/auth/auth.routes.ts` — `authRoutes(fastify)` registers `POST /auth/login` (200). Parse `request.body` as `{ email, password }` with a guard (reject non-string with ValidationError), call `authService.login`, return `{ token, profile }`. Reuse the `resolveActor`/`sendError` shape from `src/modules/leave/leave.routes.ts` for error mapping (AppError -> `{ error, code }`, else 500). No controller file. (3) NEW `src/modules/auth/index.ts` re-exporting `IAuthService`, `AuthService`, `authRoutes`. (4) EDIT `src/shared/auth/index.ts` — add `'/auth/login'` to the `PUBLIC_PATHS` set so the endpoint is reachable WITHOUT a token. (5) EDIT `src/app.ts` — `app.register(authRoutes)`. This phase depends on `src/modules/employee` (getEmployeeByEmail, EmployeeProfile) from Phase 2 and `src/shared/auth` signToken.

## Phase 5: Phase 5 — Balance: getCurrentBalances + GET /balances/me (~3 files)

Add the balance read service and route. Files: (1) EDIT `src/modules/balance/balance.service.ts` — add `getCurrentBalances(employeeId: string): Promise<Array<LeaveBalance & { available: number }>>` to `IBalanceService` and implement it. It must: fetch the employee via `employeeService.getEmployeeById`, fetch ALL policies via `policyService.getAllPolicies()` (from Phase 3), select AT MOST ONE policy per leaveTypeCode (status ACTIVE, `effectiveFrom <= asOf`, `effectiveTo IS NULL OR effectiveTo >= asOf`; if multiple remain take the latest `effectiveFrom` — use `LeavePolicyStatus` imported from `../policy`, never a bare `'ACTIVE'` string), compute the current accrual period for each via `periodContaining(employee.hireDate, policy.accrualPeriodMonths, new Date())` imported from `src/shared/date` (Phase 1), look up the balance with `repository.findByKey`, and OMIT any leave type with no balance row (never throw, never synthesize). Return a list (possibly `[]`) each entry carrying leaveTypeCode, periodStart, periodEnd, entitledDays, usedDays, pendingDays and computed `available = entitledDays - usedDays - pendingDays`. (2) NEW `src/modules/balance/balance.routes.ts` — `balanceRoutes(fastify)` registers `GET /balances/me` (200): resolve actor from `request.user` (reuse the resolveActor/sendError shape from `src/modules/leave/leave.routes.ts`), call `balanceService.getCurrentBalances(actor.id)`, return the list. No controller. (3) EDIT `src/modules/balance/index.ts` — re-export `balanceRoutes`. (4) EDIT `src/app.ts` — `app.register(balanceRoutes)`. Read-only: no transaction, no writes. This phase depends on Phase 1 (date helpers), Phase 3 (getAllPolicies), and the existing `createLeaveService`-style factory pattern.

## Phase 6: Phase 6 — Leave reads: list/getById + GET /leaves, GET /leaves/:id (~4 files)

Add leave read operations and routes. Files: (1) EDIT `src/modules/leave/leave.repository.ts` — extend `findByQuery` to honor `params.employeeIds` (added to `LeaveRequestQueryParams` in Phase 1): when present and non-empty, push `employee_id = ANY($n)` with the array as a single parameter (covers all three roles). Do NOT write SQL in the service. (2) EDIT `src/modules/leave/leave.service.ts` — add `list(actor: LeaveActor, params: LeaveRequestQueryParams): Promise<LeaveRequest[]>` and `getById(actor: LeaveActor, requestId: string): Promise<LeaveRequest>` to `ILeaveService` and implement. Role scoping: EMPLOYEE -> `employeeIds: [actor.id]`; MANAGER -> `employeeIds: [actor.id, ...(await employeeService.getEmployeesByManagerId(actor.id)).map(e => e.id)]` (direct reports plus self, one level only); ADMIN -> no employeeIds filter (sees all). `getById` loads via `repository.findById` and applies the SAME visibility rule — if the caller may not see it, throw `NotFoundError('Leave request not found')` (identical to a nonexistent id, so the endpoint cannot probe ids). Reads are status-unrestricted (a manager sees direct reports' requests in EVERY status). No transaction, no writes. (3) EDIT `src/modules/leave/leave.routes.ts` — add `GET /leaves` (200) and `GET /leaves/:id` (200). Parse query params from the wire: `status`, `leaveTypeCode` as strings (validate enum membership), `startDateFrom`/`startDateTo`/`endDateFrom`/`endDateTo` as date strings converted to `Date` (reject invalid with ValidationError, mirroring `parseCreateBody`), `limit`/`offset` as integers. Resolve actor via the existing `resolveActor`, call the service, return the result. (4) EDIT `src/modules/leave/index.ts` — no new exports needed (ILeaveService already exported). This phase depends on Phase 1 (employeeIds on LeaveRequestQueryParams) and Phase 2 (getEmployeesByManagerId).

## Phase 6: Phase 6: LeaveRequest service

Create src/modules/leaveRequest/leaveRequest.service.interface.ts with ILeaveRequestService interface: create(dto: CreateLeaveRequestDto): Promise<LeaveRequest>, approve(id: string, approverId: string): Promise<LeaveRequest>, reject(id: string, approverId: string): Promise<LeaveRequest>, cancel(id: string, employeeId: string): Promise<LeaveRequest>, findById(id: string): Promise<LeaveRequest | null>, findByEmployeeId(employeeId: string, query?: LeaveRequestQueryParams): Promise<LeaveRequest[]>. Create src/modules/leaveRequest/leaveRequest.service.ts implementing ILeaveRequestService. The create method must: validate the leave type exists via ILeaveTypeRepository, validate an active policy exists via ILeavePolicyRepository, check balance sufficiency via ILeaveBalanceRepository, validate no overlapping requests, then create the request and update pendingDays on the balance. The approve/reject methods must update the request status and adjust balance usedDays/pendingDays. Inject repositories via constructor. Update src/modules/leaveRequest/index.ts to export the new service and interface. Include Jest unit tests in tests/unit/modules/leaveRequest/leaveRequest.service.test.ts with mocked repositories. This phase depends on all model/repository files from Phases 2-5 — read them before generating any code.

## Phase 7: Phase 7: LeaveRequest controller and routes

Create src/modules/leaveRequest/leaveRequest.controller.ts with LeaveRequestController class. It receives ILeaveRequestService via constructor. Methods: create(request, reply), approve(request, reply), reject(request, reply), cancel(request, reply), getById(request, reply), getByEmployeeId(request, reply). Each method extracts params/body from the Fastify request, calls the service, and returns the appropriate HTTP status. Use Zod (already in package.json) for input validation on create/update payloads per GP-003. Create src/modules/leaveRequest/leaveRequest.routes.ts exporting a Fastify plugin that registers routes: POST /leave-requests, GET /leave-requests/:id, GET /leave-requests/employee/:employeeId, PATCH /leave-requests/:id/approve, PATCH /leave-requests/:id/reject, PATCH /leave-requests/:id/cancel. Update src/modules/leaveRequest/index.ts to export the controller and routes. Include Jest unit tests in tests/unit/modules/leaveRequest/leaveRequest.controller.test.ts with a mocked service. This phase depends on src/modules/leaveRequest/leaveRequest.service.interface.ts and src/modules/leaveRequest/leaveRequest.model.ts from Phases 5-6 — read them before generating any code.

## Phase 8: Phase 8: Wire leave routes into the Fastify app

Update src/app.ts to import and register leaveRequestRoutes from src/modules/leaveRequest/leaveRequest.routes.ts.
